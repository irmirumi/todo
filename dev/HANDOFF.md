# 또박 유지보수 인수인계

또박의 유지보수(기능 추가, 수정, 최적화)를 새 대화에서 이어 가기 위한 문서다.
처음 한 번 끝까지 읽고 시작한다. 마지막 갱신: 2026-10-31, **2.8.0** 배포 직후.

---

## 1. 한눈에

- **무엇**: 한 사람(사용자 본인)이 폰과 PC에서 같이 쓰는 할 일·시간표 PWA.
- **주소**: https://irmirumi.github.io/todo/ (GitHub Pages. `main`에 푸시하면 GitHub Actions가 `dev/`를 빌드해서 올린다)
- **저장**: Firebase. 로그인은 이메일·비밀번호, 데이터는 Firestore(프로젝트 `my-todo-e4949`). 무료 요금제다.
- **알림**: Cloudflare Workers 무료 플랜 + D1.
  - Worker 주소: `https://ttobak-reminder.irmirumi.workers.dev`
  - D1 데이터베이스: 이름 `ttobak`, Worker 변수 이름 `DB`
  - 크론: `* * * * *`
- **비용**: 0원이 조건이다. 사용자가 "추가 지불 없는 게 확실할 때만" 진행하라고 했다.
  - Firebase Blaze처럼 카드 등록이 필요한 방식은 쓰지 않는다.
  - Cloudflare는 카드 없이 쓰고 있어서, 한도를 넘으면 요청이 거절될 뿐 요금이 나가지 않는다.

## 2. 사용자와 일하는 방식

- **말투**: 반말, 편한 동료처럼. 맞장구만 치지 말고 이견이 있으면 말한다.
- **질문**:
  - 사용자만 알 수 있는 것(목적, 상황, 이미 정한 조건)만, 시작 전에 한 번, 고르기 쉬운 선택지로 묻는다.
  - 구조, 표현, 기술처럼 맡긴 것은 묻지 말고 정한 뒤, 갈렸던 선택만 끝에 한 줄로 알린다.
  - "이렇게 할까?" 같은 사전 확인, "더 필요한 거 있어?" 같은 마무리는 하지 않는다.
  - 사용자 조건이 틀렸다고 보이면 질문하지 말고 이견으로 말한 뒤, 사용자 조건대로 진행한다.
- **위임**: 사용자는 "유연하게, 합리적 판단 하에 알아서", "셀프 피드백도 해"를 자주 쓴다. 맡기면 스스로 점검하고 고칠 것까지 고친다.
- **역할(2.6.0 뒤 사용자 결정)**: Claude가 **PM·시니어 개발자·UX/UI 디자이너**를 함께 맡는다. 다른 AI와의 협업은 끝났다(기록은 `dev/reviews/`).
  - PM: 무엇을 왜 할지, 우선순위, 사용자만 알 수 있는 것(쓰는 습관·취향)만 묻기. 남은 일은 9장에 둔다.
  - 개발: 두 기기 동시 사용·오프라인·무료 한도를 먼저 생각한다. 바꾼 동작엔 테스트를 더한다.
  - 디자인: 화면을 바꾸면 `dev/tools/shots.py`로 폰·PC × 밝음·어두움을 찍어 직접 본다. 문구를 바꾸면 `dev/tools/strings_export.py`로 전체 목록을 뽑아 용어(6장)가 섞이지 않았는지 본다.
  - 혼자 만들고 혼자 검토하는 구조라, 큰 변경은 끝에 "처음 보는 사람" 눈으로 한 번 더 본다(새 화면을 실제로 따라가 보기).
- **개발 지식**: 사용자는 개발을 잘 모르고 영어 화면을 어려워한다. 외부 서비스(Cloudflare, Firebase, GitHub) 화면에서 뭔가를 시킬 때는 이렇게 한다.
  - 누를 곳을 화면 글자 그대로(영어) 굵게 적고, 무슨 뜻인지 한국어로 설명한다.
  - 막히면 화면을 캡처해서 보내 달라고 한다.
- **보고**: 끝나면 무엇이 바뀌었는지, 폰에서 무엇을 하면 되는지(보통 "1~2분 뒤 앱을 두 번 닫았다 열기"), 테스트에서 확인한 것과 못 한 것을 짧게 알린다.
- **디자인 피드백 기록** (같은 지적이 반복되지 않게)
  - 둥근 사각형의 **한쪽 면에만 테두리나 선을 넣지 않는다.** 두 번 지적받았다. 오늘 날짜 박스와 시간표 블록이었다. 1.8.0 점검 때 카테고리 관리 카드 사이 선에서 또 찾아 고쳤다. 구분선은 둥글지 않은 요소에 넣거나 `::before` 직선으로 넣는다.
  - 세로 정렬이 따로 노는 것에 민감하다. 크기가 다른 글자를 한 줄에 둘 때는 baseline으로 맞춘다.
  - 폰에서 여백을 너무 줄이면 "구려 보인다"고 한다. 글자만 살짝 줄이고 간격은 확보한다.
  - 페이드아웃 같은 촌스러운 연출은 싫어한다. 모션은 짧고 가볍게 한다.

## 4. 빌드와 배포 절차 (2.5.0~)

1. `dev/src/`(와 필요하면 `dev/assets/`)만 고친다.
2. `dev/VERSION`을 올리고, `dev/src/pwa/README.md` 맨 위에 버전 기록을 한 줄 넣는다. `ui.js`·`sw.js`에는 `__VERSION__` 자리표시자만 있다(직접 고치지 않는다).
3. 로컬 확인: `python3 dev/build.py` → `bash dev/tests/run_all.sh`
4. 커밋해서 `main`에 푸시한다(커밋 메시지는 한국어, "또박 x.y.z: 요약").
5. **GitHub Actions `deploy` 워크플로**가 빌드 → 테스트 전부 → Pages 배포를 한다. 테스트가 하나라도 실패하면 배포하지 않는다.
   ```bash
   gh api "repos/irmirumi/todo/actions/runs?per_page=3" --jq '.workflow_runs[] | [.name, .head_sha[0:7], .status, .conclusion] | @tsv'
   ```
   - `deploy`가 `completed success`인지 본다. 실패 이유는 작업 로그를 못 받으니(프록시) 주석으로 본다: `gh api repos/irmirumi/todo/actions/runs/<run id>/jobs` → 작업 id → `gh api repos/irmirumi/todo/check-runs/<작업 id>/annotations`. `run_all.sh`가 GitHub Actions에서는 실패한 테스트를 `::error`로 남긴다.
6. 사용자 폰: 앱을 열면 뒤에서 새 버전을 받고 **"새 버전이 있어요 [새로고침]"**이 뜬다. 누르면 바뀐다(앱을 완전히 닫았다 열어도 바뀐다).

**전환(2.5.0, 완료)**: 2026-10-29 사용자가 Pages Source를 **GitHub Actions**로 바꿨고, 루트의 옛 배포본 파일은 지웠다. 이제 루트에 복사하지 않는다. 혹시 누가 Source를 다시 'Deploy from a branch'로 돌리면 사이트가 빈 루트를 서빙하게 되니, 사이트가 안 열리면 이 설정부터 본다.

**알림 서버(`worker.js`)를 바꿨을 때만**: 사용자가 Cloudflare 대시보드의 Worker → **Edit code**에 파일 전체를 붙여넣고 **Deploy**해야 한다. 자동 배포는 없다.

**환경 제약**: `gh api`의 Pages 설정 API, Actions 작업 로그 다운로드, git 태그 푸시는 프록시에 막힌다. 일반 `git push`(워크플로 파일 포함)와 runs·jobs·annotations 조회는 된다.

## 5. 아키텍처와 데이터

### 5.1 저장소 어댑터
`TodoApp.boot(store)` 하나로 화면이 뜬다. store 인터페이스는 `ui.js` 맨 위 주석에 있다.
- 메서드: `start(cb)`, `set(id,body)`, `update(id,patch)`, `remove(id)`, `saveCats(cats)`, `importAll(data)`, `signIn`, `signOut`, `email`, `push`
- **조건부 쓰기(2.6.0, 있으면 씀)**: `create(id,body)`(없을 때만 만듦), `raise(id,field,value)`(더 클 때만 올림), `removeIf(id,field,value)`(그 값일 때만 지움). Firebase는 트랜잭션이라 **오프라인이면 실패**하고 다음 서버 스냅샷 때 다시 한다. 자동 추가·`madeUntil`·휴지통 비우기만 이걸 쓴다. 없는 store(테스트 목업)는 화면 데이터로 확인하는 대체 경로를 탄다(`createTask`·`raiseTpl`·`removeIf`)
- `cb.onData(d, meta)`: `meta.server`(캐시 아님·올리는 중 없음)를 `S.fresh`로 둔다. **자동 추가·휴지통 비우기(`daily`)는 `S.fresh`이고 온라인일 때만** — 들어오는 곳은 새 스냅샷, 연결 완료(`onStatus live`), 날짜 바뀜(`tick`)
- **편집 저장은 바꾼 칸만(2.6.0)**: 창을 열 때 값(`S.edit._base`)과 비교해 다른 칸만 `update`한다(`diffOf`). 다른 기기가 그사이 고친 다른 칸을 덮지 않는다. 같은 칸을 양쪽에서 고치면 나중 것이 이긴다(세부 할 일 목록은 통째로 한 칸)
- `cb.onData`가 받는 것: `{tasks, cats, tpls, events}`. `tasks`, `tpls`, `events`는 Map이다.
- 테스트는 `TodoApp.memoryStore()`를 쓴다. 문서 id 접두어로 Map을 나눈다.

### 5.2 Firestore 경로
`users/{uid}/items/{docId}`, 보안 규칙은 본인만 읽고 쓰기(`firestore.rules`). 문서 종류는 id 접두어로 구분한다.

| 접두어 | 의미 | 주요 필드 |
|---|---|---|
| `t_` | 할 일 | `title, note, date(YYYY-MM-DD|null), time(HH:MM|null), end, remind(분|null), cat, sub, done, doneAt, skipped, skippedAt, createdAt, subtasks[{id,t,done}], tpl, postponed(미룬 횟수, 2.5.0), deletedAt(휴지통, 2.5.0 — 화면은 `S.trash`로 따로 두고 30일 뒤 지움), from·fromDate·again(다시 넣은 할 일: 원래 id·날짜·몇 번째), later·laterDate(안 함 한 원래 할 일: 다시 넣은 id·날짜)` — 1.5.0의 `due, dueTime, dueRemind`가 남아 있을 수 있지만 1.7.0부터 안 쓴다(화면·알림·가져오기 모두 무시) |
| `m_` | 메모(2.8.0) | `text`(간단한 마크다운, 2만 자), `color`("" 또는 c1~c8), `x, y, w, h, z`(PC 보드의 자리·크기·겹침 순서), `createdAt, updatedAt, deletedAt`(휴지통) — 날짜와 상관없다(사용자와 논의: 포스트잇은 계속 보이는 게 핵심, 날짜에 묶인 건 할 일 메모로). 묶기(archive) 대상 아님 |
| `r_` | 반복 할 일(매주 템플릿) | `title, note, time, end, remind, cat, sub, days[0-6], until, archived, auto(없으면 켬), madeUntil, subtasks[{id,t}], createdAt` — **자동 추가(2.5.0, 2.6.0 보강)**: 서버 최신 데이터일 때 오늘·내일 것을 `t_<원본id 뒤>_<YYYYMMDD>` 고정 id로 **없을 때만**(`create`) 만들고, 다 끝난 뒤 `madeUntil`을 **올리기만**(`raise`) 한다. 고정 id만으로는 늦게 도착한 쓰기가 먼저 생긴 쪽의 완료·편집을 덮을 수 있어서(Codex C1) 트랜잭션으로 바꿨다. 지워도 다시 안 만듦 |
| `e_` | 고정 일정(수업 등) | `title, place, color(c1~c8), days, time, end, slots?[{id,days,time,end}], from, until, holOff, remind, note, skips[날짜], ovr{키:{time?,end?,place?}}(바꾼 칸만, 2.4.0), 쓰기는 필드 단위(`skips`는 `store.fx.union/remove`, `ovr.<키>`는 경로 쓰기·`fx.del`, 2.5.0 — 400개 넘으면 그때만 통째로 정리), archived, createdAt` — `ovr`은 이 날만 바꾼 시간·장소(1.7.0), `eventsOn`이 합쳐서 돌려주고(`chg` 표시) 알림도 이 값을 쓴다. 60일 지난 건 저장할 때 지운다. **`slots`(2.3.0, 2.3.1에 다시 짬)**: `[{id,days,time,end}]` 요일·시간 줄 여러 개. **같은 요일이 여러 줄에 있어도 된다**(중간에 쉬는 수업). `ovr`·`skips` 키는 `occKey(날짜,id)`: id `""`인 줄은 날짜 그대로(예전 데이터와 호환), 나머지는 `날짜#id`(`KEY_RE`). `days·time·end`는 id `""`인 줄(없으면 첫 줄)과 같게 저장(예전 버전용). 줄이 하나이고 id가 `""`면 `slots:null`. 읽을 땐 반드시 `slotsOf`/`evBase(e,k,sid)`/`evAt(e,k,sid)`를 거치고, 화면 요소엔 `data-s`(줄 id)를 단다. `e.time`을 바로 쓰면 한 줄만 나온다 |
| `a_YYYY-MM` | 묶인 옛 기록(1.4.0) | `tasks: {t_id: 할 일 본문}` — 60일 지난 완료·안 함. `archive.js`가 하루 한 번(기기별 localStorage `ttobak.arch.<uid>`) 묶고, 화면에는 보통 할 일로 펼쳐 준다. 고치거나 지우면 `writeOps`가 원래 문서로 되살리며 묶음에서 뺀다(한 쓰기 묶음으로). 같은 id가 따로도 있으면 따로 있는 쪽이 이기고, 옛 사본은 다음 묶기 때 지운다 |
| `meta` | 카테고리 | `cats: [{id, name, color, subs:[{id,name}], archived?}]` (배열 순서 = 화면 순서) |

- **Firestore는 `undefined` 필드를 거부한다.** 쓰는 객체에는 반드시 `null`이나 실제 값을 넣는다.
- 가져오기(import)는 `clean()`, `cleanTpl()`, events 정리 코드에서 id 패턴과 값을 검증한다. 세부 할 일 id 검증은 XSS를 막으려고 넣은 것이다.

### 5.3 화면 구조 (`ui.js`)
- **탭 3개**
  - **달력** (`view="day"`, 2.4.0까지 이름은 '캘린더'): 달력, 그날 고정 일정 줄, 카테고리별 카드. 반복 할 일은 흐린 줄('추가 예정'·'눌러서 추가')로 보이고 ＋로 추가한다.
  - **시간표** (`view="week"`): 월요일 시작 주간. 고정 일정은 진한 칸, 할 일은 연한 칸, 반복 할 일은 빗금. 위에 '시간 미정' 줄(시간 없는 할 일 + 전날부터 이어진 칩. 이어짐만 있으면 이름이 '이어짐')이 있고, 빈칸을 누르면 할 일이나 고정 일정을 추가한다. 좁은 화면에서 겹치는 것들은 "n개" 묶음이 되고, 누르면 목록이 뜬다.
  - **전체** (`view="all"`): '밀린 할 일 N개'는 접힌 한 줄이고 펼치면 줄마다 '날짜 옮기기'. 나머지는 날짜별 카드, 그 뒤에 날짜 없음, 맨 아래 '기록'(안 함 최근 100·완료 최근 150, 소제목으로 나눔). 2.4.0에 '날짜순'·'앞으로 N개' 없앰.
- **정렬**
  - 캘린더 카드 안: 소분류 순서 → 시간 있는 것(빠른 순) → 시간 없는 것(가나다). `inCatOrder`
  - 전체 탭 하루 안: 시간 → 카테고리 순서 → 소분류 순서 → 가나다. `allOrder`
- **시트** (`<dialog>` 하나를 돌려 씀): `S.sheet` 값은 아래와 같다.
  - 편집 계열: `edit`, `tpl`, `ev`, `evday`, `cats`. **2.2.0부터 '저장'(`data-act="save"` → `saveDlg()`, `S.saveReq`)을 눌렀을 때만 commit.** 바깥·뒤로·Esc·아래로 밀기로 닫으면 버리고, 연 뒤 바뀐 게 있으면(`snapOf` 비교) '저장 안 하고 닫았어요 [다시 열기]' 토스트 → `reopenDraft`가 고치던 그대로 다시 연다. 보관·복원·내일로·원래대로·엔터는 저장으로 친다. **2.4.0**: '저장'·엔터는 `saveChecked()`(`saveBlock`)를 거쳐 시작=종료, 요일·시작 시간 없는 고정 일정이면 막고 알림만. 편집 창의 '넘기기'·'다른 날에 추가'·'반복 할 일로 등록'은 열 때 저장하지 않고 초안을 들고 가서(`holdDraft` → `S.laterDraft`/`S.parentDraft`) 다음 창에서 확정할 때 `applyDraft`로 함께 저장, 취소하면 '변경 사항을 저장하지 않았어요 [다시 열기]'
  - 그 밖: `info`, `group`, `slot`, `cats`, `menu`, `tpls`, `evs`, `notify`, `export`, `import`
- **렌더링**: morphdom으로 바뀐 부분만 고친다. 입력 중인 칸과 포커스는 건드리지 않는다. 일시적인 애니메이션 클래스는 `TRANSIENT` 목록으로 유지한다.
- **이벤트**: `document` 클릭 위임 하나에서 `data-act` 값으로 `switch`한다. 로딩 중에는 쓰기 동작을 막는다(`S.mode==="loading"` 정규식).

### 5.4 알림 흐름
1. 앱 `push.js`가 앞으로 62일 안에 울릴 알림을 계산해서(최대 300개) Worker `/sync`로 통째로 보낸다. 해시가 같으면 보내지 않는다.
   - 대상: 할 일, 고정 일정(요일·기간·공휴일·쉼 반영)
   - 빼는 것: 완료, 안 함, 보관된 카테고리, 이미 지난 알림
2. 서버에서 받은 스냅샷일 때만 보낸다(`fromCache` 제외). 화면이 가려지는 순간에는 `keepalive`로 바로 보낸다.
3. Worker가 매분 크론으로 20초 안에 울릴 알림을 찾아 Web Push로 보낸다. 실행당 최대 4개, 1시간 넘게 밀린 건 버린다.
4. Worker 보안
   - Firebase ID 토큰(RS256)을 검증한다.
   - 처음 쓴 계정 하나만 받는다(D1 `kv.owner`). 바꾸려면 D1 콘솔에서 `DELETE FROM kv WHERE k='owner'`
   - 푸시 서비스 호스트만 허용한다.
   - `/sync`는 쿼리 2개(`json_each`)로 처리한다. D1 무료 한도가 실행당 50쿼리라서다.
5. iOS는 16.4 이상, 홈 화면에 추가한 앱에서만 알림을 받는다.

  - 조합 중의 엔터는 `compositionend`를 기다렸다가 처리한다(`pendingEnter`). 안 하면 안드로이드에서 추가가 안 되거나 두 번 된다.

  - 고정 id로 `set`하면 문서 수는 하나지만 늦게 도착한 쪽이 먼저 생긴 쪽의 완료·편집을 덮는다. 자동으로 만드는·지우는 쓰기는 조건부(`create`·`raise`·`removeIf`)로 한다.
  - 가짜 Firebase에서 '다른 기기가 막 쓴 것'은 `__fs.docs`에 넣고 `__fs.view[경로]=null`(또는 옛 값)로 이 기기 스냅샷에서 가린다. `__fs.offline=true`면 트랜잭션이 실패한다. `__fs.emit()`으로 스냅샷을 다시 보낸다.
- **요일·시각에 따라 깨지는 테스트**(2.5.0 시각, 2.8.0 토요일)
  - 실제 오늘을 쓰는 테스트는 그 요일·시각에만 깨질 수 있다. 시간표는 일요일 시작이라 **토요일엔 '내일'이 다음 주**로 넘어가 칸이 안 보였다(test_v24·test_views). 지금 선은 9~18시 밖이면 안 그린다. 시계를 고정하거나(`pg.clock.install`), 보이는 칸에서 날짜를 읽어 확인한다.
